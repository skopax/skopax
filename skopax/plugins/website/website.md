`page` and `screenshot` read the configured website as a visitor without cookies sees it.

- `page` is one plain GET with up to 3 redirects, each hop reported. Use it for status, redirect, cache and "is this text on the page" questions; it opens no browser.
- Every `page` answer carries `at`, and the `age` header when the cache sent one (without it the copy's age is unknown): when `at` minus age is before a deploy, the copy is older than the release, so say "not checked, cached copy" instead of calling a change missing or a page fine. Your own first load can warm the cache, so a hit on a second load says little.
- A soft 404 answers 200 with a not-found page (its title or h1 says so, or it is far smaller than its siblings). Old or renamed URLs that arrive only from outside (no referrer, crawlers): check with `page` whether a redirect exists, and with `find` on listings and the sitemap whether a stale link is still published; list the old URLs that still lack a redirect.
- A card about a page that is down cannot tell when the page is back: check it with `page` before the draft and in every later run, and end the note with the time and status of your last check.
- `screenshot` loads the page in the headless browser of the instance and shows you the picture. Use it when how the page looks matters. It is slower and capped per run and per day.
- Both refuse /api/ paths, login pages, click-counting paths and ad-tracking parameters, and both stay on the site hosts. A refusal is the rule working, not the site failing.
- A Cloudflare challenge is the answer of Cloudflare to the check, never the status of the page.
- The browser blocks other hosts and every /api/ call, so a section that the page fills in later in the browser may be empty in a screenshot while visitors see it.
- A `browser-down|<host>` card means the screenshot browser has not answered for 5 min; screenshots wait for it. An `access|-/website|browser` card means the browser service refused the read.
- `pass_table` source `browser` holds one row per instance: whether the browser answers, its version and when it last answered.
- `page_scan` loads a page without a picture and returns its text lines, the code layout checks and what the scheduled page scan last found there. It does not measure boxes that scroll sideways or are cut off; take a `screenshot` for that.
- The page scan (switched on with `website.page-scan`) opens `page-typos|<page>` and `page-layout|<page>` cards. A box that scrolls inside the page is fine and opens no card; it becomes a sev info note only when a model claim says something in it is cut off. Content clipped only by the page itself can be reached by panning, so it counts as a page wider than the screen. A clipped box counts as cut off only when readable content (text, links or controls) lies more than 4 px past its clipping edge; decoration is not reported: aria-hidden parts, images and SVG, pseudo-elements, transformed or animated parts, text cut with an ellipsis and visually hidden screen-reader text. Boxes cut off the same way are one finding that counts them and marks each. The card text and its screenshot say what code measured; trust those facts over a guess from a picture.
- `pass_table` source `pageScan` holds the last scan: one row per page read, the pages that did not load and a summary row.
- Instance options: tracking-params adds query parameters that count as ad tracking, kept-headers adds response headers to what `page` returns (never cookies), scan-skip adds path prefixes the page scan never reads, and user-agent replaces the built-in User-Agent of `page`. A page the scan skips has no row in `pass_table` source `pageScan`.
